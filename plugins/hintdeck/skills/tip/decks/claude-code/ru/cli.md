# cli — флаги запуска, headless, пайпы

## cli-pipe — в claude -p можно направить данные пайпом
<!-- n: 63; verified: 2.1.278 -->
Неинтерактивный режим читает stdin, поэтому Claude встраивается в конвейер как обычная утилита: `cat build-error.txt | claude -p 'кратко объясни причину' > out.txt`. Лимит на stdin — 10 МБ; для больших данных запиши их в файл и укажи путь в промпте.

**Попробуй:** `git diff | claude -p 'найди в этом диффе рискованные места'`.

## cli-json-schema — claude -p может вернуть JSON строго по твоей схеме
<!-- n: 64; verified: 2.1.278 -->
`--output-format json` возвращает результат с метаданными: id сессии, расход, `total_cost_usd`. Добавь `--json-schema '<схема>'` — и в поле `structured_output` придёт объект, валидный по твоей JSON Schema. Это превращает Claude в предсказуемый шаг скрипта.

**Попробуй:** `claude -p "перечисли функции в main.py" --output-format json --json-schema '{"type":"object","properties":{"functions":{"type":"array","items":{"type":"string"}}},"required":["functions"]}'`.

## cli-continue — claude -c продолжает последний разговор в этом каталоге
<!-- n: 65; verified: 2.1.278 -->
`claude -c` поднимает самый свежий разговор текущего каталога, `claude -r <имя|id> "запрос"` — конкретный, сразу с новым сообщением. Работает и неинтерактивно: `claude -c -p "проверь ошибки типов"` дописывает ход в ту же сессию. `-c` пропускает сессии, созданные через `claude -p`.

**Попробуй:** утром вместо пересказа вчерашнего — `claude -c`.

## cli-from-pr — claude --from-pr находит сессию, создавшую pull request
<!-- n: 66; needs: git; verified: 2.1.278 -->
Сессии автоматически привязываются к PR, которые в них создал Claude. `claude --from-pr 123` открывает список сессий, связанных с этим PR (принимает номер либо ссылку GitHub, GitLab или Bitbucket), — удобно вернуться к контексту, когда пришли комментарии ревью.

**Попробуй:** получив ревью на PR, сделанный с Claude, выполни `claude --from-pr <номер>`.

## cli-bare — --bare ускоряет скриптовые вызовы
<!-- n: 67; verified: 2.1.278 -->
`claude --bare -p "..."` пропускает автообнаружение хуков, скиллов, команд, сабагентов, плагинов, MCP-серверов, авто-памяти и CLAUDE.md — скриптовый вызов стартует быстрее и не зависит от твоей личной конфигурации. У Claude остаются Bash, чтение и правка файлов.

**Попробуй:** сравни по времени `claude -p "2+2"` и `claude --bare -p "2+2"`.

## cli-safe-mode — --safe-mode запускает сессию без всех кастомизаций
<!-- n: 68; verified: 2.1.278 -->
Если Claude Code ведёт себя странно, `claude --safe-mode` стартует без CLAUDE.md, скиллов, плагинов, хуков, MCP, своих команд и агентов, тем, keybindings и статусной строки; авторизация, модель и разрешения работают как обычно. Проблема исчезла — виновата одна из этих поверхностей. Для чистоты эксперимента: `cd /tmp && CLAUDE_CONFIG_DIR=/tmp/claude-clean claude`.

**Попробуй:** при следующей необъяснимой странности первым делом `claude --safe-mode`.

## cli-budget-limits — в headless-запуске можно ограничить бюджет и число ходов
<!-- n: 69; verified: 2.1.278 -->
Для `claude -p` есть предохранители: `--max-budget-usd 2` останавливает работу по достижении суммы (расход сабагентов учитывается), `--max-turns 10` ограничивает число агентных ходов и завершает запуск с ошибкой при превышении. Обязательны для скриптов и CI, где никто не смотрит на экран.

**Попробуй:** добавь `--max-budget-usd` в любой свой скрипт с `claude -p`.

## cli-settings-inline — --settings переопределяет настройки на одну сессию
<!-- n: 70; verified: 2.1.278 -->
`claude --settings ./exp.json` или `claude --settings '{"effortLevel":"low"}'` переопределяет заданные ключи только для этой сессии; остальные берутся из файлов как обычно. `--setting-sources user,project` выбирает, какие файлы настроек вообще читать.

**Попробуй:** проверь экспериментальную настройку через `--settings`, не трогая `settings.json`.

## cli-system-prompt — --append-system-prompt добавляет правила, --system-prompt заменяет всё
<!-- n: 71; verified: 2.1.278 -->
`--append-system-prompt "..."` дописывает текст к системному промпту по умолчанию — безопасный способ задать правила на один запуск; вариант с `-file` читает текст из файла. `--system-prompt` заменяет промпт целиком вместе со встроенными инструкциями — нужен редко и осознанно.

**Попробуй:** `claude --append-system-prompt "Отвечай только diff-ом" -p "переименуй foo в bar в utils.py"`.

## cli-tools-restrict — --tools и --disallowedTools ограничивают инструменты запуска
<!-- n: 72; verified: 2.1.278 -->
`--tools "Bash,Edit,Read"` оставляет только перечисленные встроенные инструменты (`""` — ни одного). `--disallowedTools "mcp__*"` убирает все MCP-инструменты из контекста, а правило вида `Bash(rm *)` оставляет инструмент, но запрещает подходящие вызовы. `--allowedTools "Bash(git log *)"` — что выполнять без запроса.

**Попробуй:** для безопасного анализа — `claude --tools "Read" -p "опиши архитектуру"`.

## cli-debug-filter — --debug принимает фильтр по категориям
<!-- n: 73; verified: 2.1.278 -->
`claude --debug='mcp,startup'` включает отладку только по нужным категориям; фильтр работает именно в форме с `=`. Лог сессии лежит в `~/.claude/debug/<session-id>.txt`, а `--debug-file <путь>` пишет его в указанный файл.

**Попробуй:** если MCP-сервер не отдаёт инструменты — `claude --debug=mcp` и загляни в лог.

## cli-install-version — claude install ставит конкретную версию
<!-- n: 74; verified: 2.1.278 -->
`claude update` обновляет до последней версии, а `claude install <версия>` ставит конкретную: `claude install 2.1.118`, `claude install stable`, `claude install latest`. Пригодится, чтобы откатиться, если свежий релиз сломал рабочий процесс.

**Попробуй:** `claude --version` и сравни с верхней записью в `/release-notes`.

## cli-project-purge — claude project purge удаляет локальное состояние проекта
<!-- n: 75; verified: 2.1.278 -->
`claude project purge [путь]` удаляет всё локальное состояние Claude Code для проекта: транскрипты, списки задач, отладочные логи, историю правок файлов, историю промптов и запись в `~/.claude.json`. `--dry-run` покажет, что будет удалено; без пути — интерактивный выбор.

**Попробуй:** `claude project purge --dry-run` для давно заброшенного проекта.

## cli-fallback-model — --fallback-model задаёт запасные модели при перегрузке
<!-- n: 76; verified: 2.1.278 -->
`--fallback-model` принимает список моделей через запятую: если основная перегружена или недоступна, Claude Code по порядку пробует следующие. Чтобы цепочка действовала постоянно, есть настройка `fallbackModel`.

**Попробуй:** добавь `--fallback-model sonnet` к долгому ночному `claude -p`.

## cli-permission-prompts-none — --permission-prompts none для запусков без человека
<!-- n: 77; verified: 2.1.278 -->
В headless-запуске, где отвечать на запросы некому, `--permission-prompts none` автоматически отклоняет всё, что потребовало бы вопроса; активный режим разрешений (включая auto) продолжает решать как обычно. Запуск не зависнет в ожидании ответа. Доступно с 2.1.259.

**Попробуй:** добавь флаг в cron- или CI-скрипт с `claude -p`.

## cli-auth-status — claude auth status удобен в скриптах
<!-- n: 78; verified: 2.1.278 -->
`claude auth status` печатает состояние авторизации в JSON и завершается с кодом 0, если вход выполнен, и 1, если нет; `--text` даёт читаемый вывод. Для CI есть `claude setup-token` — он выпускает долгоживущий OAuth-токен и печатает его, никуда не сохраняя.

**Попробуй:** `claude auth status --text`.
