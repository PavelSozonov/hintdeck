# context — контекст, память, CLAUDE.md

## ctx-clear-between-tasks — /clear между несвязанными задачами
<!-- n: 79; verified: 2.1.278 -->
Самый частый антипаттерн — «сессия-свалка»: начал одну задачу, спросил про другое, вернулся к первой. Контекст забит нерелевантным, качество падает, а каждое следующее сообщение оплачивает этот балласт. Между несвязанными задачами делай `/clear`; перед этим `/rename`, чтобы потом найти разговор через `/resume`.

**Попробуй:** закончив задачу — `/rename <что сделано>` и `/clear`.

## ctx-two-corrections-rule — две неудачные правки подряд — повод начать заново
<!-- n: 80; verified: 2.1.278 -->
Если ты дважды поправил Claude по одному и тому же вопросу, а результат всё ещё не тот, контекст уже засорён неудачными попытками. Лучше `/clear` и новый, более точный промпт, учитывающий то, что ты понял. Чистая сессия с хорошим промптом почти всегда обгоняет длинную сессию с накопленными исправлениями.

**Попробуй:** на третьей правке одного и того же остановись и перепиши исходный промпт.

## ctx-claude-md-scopes — у CLAUDE.md четыре уровня, и подкаталоги грузятся лениво
<!-- n: 81; verified: 2.1.278 -->
Инструкции читаются из нескольких мест: `~/.claude/CLAUDE.md` (личное, для всех проектов), `./CLAUDE.md` или `./.claude/CLAUDE.md` (проектное, в git), `./CLAUDE.local.md` (личное для проекта, в `.gitignore`); поверх них организация может добавить managed-файл. Файлы выше рабочего каталога грузятся при старте, а CLAUDE.md в подкаталогах — только когда Claude читает файлы из них.

**Попробуй:** вынеси личные URL песочниц и тестовые данные из общего CLAUDE.md в `CLAUDE.local.md`.

## ctx-imports — CLAUDE.md умеет импортировать файлы через @путь
<!-- n: 82; verified: 2.1.278 -->
Строка вида `@docs/git-instructions.md` в CLAUDE.md подгружает файл в контекст при старте; относительные пути считаются от файла с импортом, вложенность — до четырёх уровней. Чтобы упомянуть путь без импорта, оберни его в обратные кавычки. Личные инструкции, общие для всех worktree репозитория, удобно держать дома: `@~/.claude/my-project.md`.

**Попробуй:** замени скопированный в CLAUDE.md кусок README на `@README.md`.

## ctx-rules-paths — правила в .claude/rules/ могут грузиться только для нужных файлов
<!-- n: 83; skip-if: rules; verified: 2.1.278 -->
Вместо одного огромного CLAUDE.md заведи `.claude/rules/*.md`, по файлу на тему. Если в frontmatter правила указать `paths: ["src/api/**/*.ts"]`, оно попадёт в контекст, только когда Claude читает подходящие файлы, — шума и расхода меньше. Правила без `paths` грузятся при старте наравне с CLAUDE.md.

**Попробуй:** вынеси из CLAUDE.md раздел про тесты в `.claude/rules/testing.md` с `paths` на каталог тестов.

## ctx-prune-claude-md — длинный CLAUDE.md выполняется хуже короткого
<!-- n: 84; verified: 2.1.278 -->
Когда CLAUDE.md разрастается, важные правила тонут в шуме, и Claude пропускает половину. Регулярно вычищай: если Claude и без инструкции делает правильно — удали её; если правило должно выполняться всегда — преврати его в хук. `/doctor` подсвечивает содержимое CLAUDE.md, которое выводится из самого кода.

**Попробуй:** перечитай CLAUDE.md и удали три пункта, которые Claude соблюдает и так.

## ctx-auto-memory — авто-память проекта лежит в ~/.claude/projects/…/memory
<!-- n: 85; verified: 2.1.278 -->
Claude сам ведёт заметки между сессиями: каталог `~/.claude/projects/<проект>/memory/` с индексом `MEMORY.md` и файлом на каждую запись. В начало каждого разговора попадают только первые 200 строк или 25 КБ индекса; остальные файлы читаются по необходимости. Память общая для всех worktree репозитория и локальна для машины. Посмотреть и поправить — `/memory`.

**Попробуй:** открой `/memory` и проверь, нет ли там устаревших записей.

## ctx-subagents-for-research — исследование отдавай сабагентам, чтобы не тратить свой контекст
<!-- n: 86; verified: 2.1.278 -->
Изучая кодовую базу, Claude читает много файлов, и все они оседают в твоём контексте. Сабагент работает в отдельном окне и возвращает только выжимку. Формулировка простая: «Use subagents to investigate how our auth handles token refresh». Основной разговор остаётся чистым для реализации.

**Попробуй:** следующий вопрос «как у нас устроено X» начни словами «используй сабагентов, чтобы выяснить…».

## ctx-scope-investigation — «исследуй» без рамок съедает контекст
<!-- n: 87; verified: 2.1.278 -->
Просьба «разберись с X» без границ приводит к чтению сотен файлов. Задавай рамки: какие каталоги смотреть, на какой вопрос ответить, в каком виде вернуть результат. Либо отдавай исследование сабагенту, чтобы оно вообще не попадало в основной контекст.

**Попробуй:** вместо «посмотри, как работает биллинг» — «в src/billing/ найди, где считается НДС, и назови функцию и файл».

## ctx-compact-skills — после сжатия контекста скиллы урезаются до 5000 токенов
<!-- n: 88; verified: 2.1.278 -->
При авто-сжатии вызванные скиллы возвращаются в контекст не целиком: сохраняются первые 5 000 токенов каждого, общий бюджет — 25 000 токенов, начиная с самого недавнего. Если вызвал много скиллов, ранние могут выпасть совсем. Если длинный скилл после сжатия «перестал работать» — просто вызови его ещё раз.

**Попробуй:** в долгой сессии после сжатия повтори вызов ключевого скилла.

## ctx-autocompact-window — /autocompact задаёт порог авто-сжатия
<!-- n: 89; verified: 2.1.278 -->
`/autocompact 500k` задаёт, при каком заполнении контекстного окна срабатывает авто-сжатие; `auto` возвращает порог, подобранный под модель. Значение сохраняется в пользовательские настройки. Только на один запуск — `claude --autocompact 500k`. Без аргумента команда показывает текущее окно. С окном в 1M токенов более ранний порог заметно удешевляет длинные сессии.

**Попробуй:** `/autocompact` — посмотри текущее значение.

## ctx-cli-over-mcp — CLI-утилиты экономнее MCP-серверов
<!-- n: 90; verified: 2.1.278 -->
Определения MCP-инструментов по умолчанию отложены (в контекст попадают только имена), но утилиты вроде `gh`, `aws`, `gcloud` всё равно экономнее: они не добавляют в контекст списков инструментов вообще — Claude просто запускает команды. Неиспользуемые серверы отключай через `/mcp`, а что занимает место — смотри в `/context`.

**Попробуй:** `/mcp` — отключи серверы, которыми не пользовался на этой неделе.

## ctx-instructions-vs-enforcement — CLAUDE.md объясняет, а запрещают хуки и permissions
<!-- n: 91; verified: 2.1.278 -->
CLAUDE.md рассказывает Claude, «как у нас принято», чтобы он принимал верные решения, — но это не гарантия. Всё, что не должно случиться никогда (правка защищённых файлов, опасные команды), обеспечивается правилами permissions и хуками: они срабатывают независимо от решения модели.

**Попробуй:** найди в CLAUDE.md правило со словом «никогда» и подумай, не место ли ему в deny-правиле или хуке.
