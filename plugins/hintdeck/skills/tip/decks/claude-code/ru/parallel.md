# parallel — worktree, фоновые сессии, параллельная работа

## par-worktree-flag — claude -w запускает сессию в изолированном worktree
<!-- n: 116; needs: git; verified: 2.1.278 -->
`claude -w feature-auth` создаёт git worktree в `.claude/worktrees/feature-auth/` на новой ветке `worktree-feature-auth` и стартует в нём: правки параллельных сессий не сталкиваются. Без имени оно сгенерируется само. При выходе чистый worktree удаляется автоматически, а если в нём есть работа — Claude спросит, оставить или удалить. Добавь `.claude/worktrees/` в `.gitignore`.

**Попробуй:** открой второй терминал и запусти `claude -w <имя-задачи>` рядом с основной сессией.

## par-worktree-pr — claude -w "#1234" открывает worktree прямо на pull request
<!-- n: 117; needs: git; verified: 2.1.278 -->
Вместо имени `--worktree` принимает номер с решёткой, ссылку на PR GitHub или MR GitLab: Claude Code забирает головной коммит из `origin` и создаёт worktree `.claude/worktrees/pr-<номер>`. Аргумент бери в кавычки, иначе shell примет `#` за комментарий. Удобно для ревью чужого PR, не трогая своё рабочее дерево.

**Попробуй:** `claude -w "#<номер PR>"` и попроси разобрать изменения.

## par-worktreeinclude — .worktreeinclude копирует .env в каждый новый worktree
<!-- n: 118; needs: git; skip-if: worktree-include; verified: 2.1.278 -->
Worktree — чистый checkout, и gitignored-файлов вроде `.env` в нём нет. Файл `.worktreeinclude` в корне проекта (синтаксис `.gitignore`) перечисляет, что копировать в каждый новый worktree; копируются только файлы, которые одновременно подходят под шаблон и игнорируются git. Действует и для worktree сабагентов.

**Попробуй:** создай `.worktreeinclude` со строками `.env` и `.env.local`.

## par-worktree-baseref — worktree по умолчанию ветвится от main, а не от твоей ветки
<!-- n: 119; needs: git; skip-if: worktree-config; verified: 2.1.278 -->
Новый worktree ветвится от основной ветки на remote (`"fresh"`), поэтому незапушенных коммитов в нём нет. Настройка `"worktree": {"baseRef": "head"}` заставляет ветвиться от локального `HEAD` — нужно, когда сабагенты в worktree должны видеть работу в процессе. Имя произвольной ветки указать нельзя — для этого создавай worktree через git вручную.

**Попробуй:** если изолированные агенты «не видят» твои свежие коммиты — поставь `baseRef: "head"`.

## par-worktree-tmux — claude -w имя --tmux открывает worktree в отдельной панели
<!-- n: 120; needs: git; verified: 2.1.278 -->
`claude -w feature-auth --tmux` создаёт для worktree tmux-сессию; в iTerm2 используются нативные панели, а `--tmux=classic` включает обычный tmux. Каждая параллельная задача получает своё окно.

**Попробуй:** `claude -w experiment --tmux`.

## par-bg — claude --bg запускает задачу в фоне и сразу возвращает shell
<!-- n: 121; verified: 2.1.278 -->
`claude --bg "разберись с нестабильным тестом X"` стартует фоновую сессию и печатает её id и команды управления. Промпт — позиционный аргумент; с `-p` флаг несовместим. Дальше: `claude agents` — обзор, `claude attach <id>` — подключиться, `claude logs <id>` — свежий вывод, `claude stop <id>` — остановить.

**Попробуй:** `claude --bg "найди и перечисли TODO в src/"`, затем `claude agents`.

## par-agent-view — claude agents: пульт управления параллельными сессиями
<!-- n: 122; verified: 2.1.278 -->
`claude agents` открывает agent view: таблица фоновых сессий со статусом — работает, ждёт тебя, готово. Промпт внизу запускает новую сессию, `Space` — быстрый просмотр и ответ без подключения, `Enter` или `→` — подключиться полностью, `←` на пустой строке — отключиться обратно. В обычной сессии подсказка `←` в футере показывает, сколько фоновых агентов ждут твоего ответа.

**Попробуй:** `claude agents` и запусти оттуда две независимые задачи.

## par-bg-exec — claude --bg --exec запускает в фоне обычную shell-команду
<!-- n: 123; verified: 2.1.278 -->
`claude --bg --exec 'pytest -x'` запускает не сессию Claude, а саму команду как фоновую PTY-задачу — она видна и управляется там же, где остальные фоновые сессии.

**Попробуй:** `claude --bg --exec '<долгая команда проекта>'` и посмотри её в `claude agents`.

## par-color-rename — /color и /rename помогают не путать параллельные сессии
<!-- n: 124; verified: 2.1.278 -->
`/color <цвет>` красит строку ввода текущей сессии (`red`, `blue`, `green`, `yellow`, `purple`, `orange`, `pink`, `cyan`; без аргумента — случайный), а `/rename` показывает имя сессии в строке ввода и заголовке терминала. Вместе они позволяют мгновенно понять, в каком из окон ты сейчас.

**Попробуй:** в каждой параллельной сессии выполни `/rename <задача>` и `/color <цвет>`.

## par-cross-session — сессии на одной машине могут писать друг другу
<!-- n: 125; verified: 2.1.278 -->
В сессиях с включённым cross-session messaging набери `@` и хотя бы одну букву — в подсказках вместе с файлами появятся другие живые сессии на этой машине, и Claude можно попросить написать выбранной. `/list-agents` (он же `/peers`) показывает, кому можно писать: сабагентов, участников agent team и другие сессии.

**Попробуй:** `/list-agents` при двух открытых сессиях.

## par-batch — /batch раскладывает большую правку на параллельных агентов
<!-- n: 126; needs: git; verified: 2.1.278 -->
`/batch <инструкция>` исследует кодовую базу, делит работу на 5–30 независимых частей и показывает план. После одобрения на каждую часть запускается фоновый сабагент в своём worktree: он реализует часть, гоняет тесты и открывает pull request. Пример: `/batch migrate src/ from JavaScript to TypeScript`.

**Попробуй:** для следующей механической миграции по многим файлам начни с `/batch` и посмотри на план.

## par-workflows — workflow: оркестрация десятков агентов скриптом
<!-- n: 127; verified: 2.1.278 -->
Динамический workflow — это JavaScript-скрипт, который пишет Claude и исполняет рантайм: цикл, ветвления и промежуточные результаты живут в скрипте, а не в контексте модели, поэтому масштаб — десятки и сотни агентов, запуск возобновляем. Подходит для аудита всей кодовой базы, миграции сотен файлов, исследования с перекрёстной проверкой. Посмотреть в деле — встроенный `/deep-research <вопрос>`; прогресс — `/workflows`.

**Попробуй:** `/deep-research <вопрос, по которому нужно сверить несколько источников>`.

## par-fan-out-script — цикл с claude -p для однотипной обработки файлов
<!-- n: 128; verified: 2.1.278 -->
Свой fan-out: попроси Claude сохранить список файлов в `files.txt`, затем `for file in $(cat files.txt); do claude -p "Мигрируй $file … Верни OK или FAIL" --allowedTools "Edit,Bash(git commit *)"; done`. Отладь промпт на первых 2–3 файлах и только потом запускай на весь список. `--allowedTools` ограничивает, что можно делать без присмотра.

**Попробуй:** прогони такой цикл на трёх файлах, прежде чем запускать на сотне.
