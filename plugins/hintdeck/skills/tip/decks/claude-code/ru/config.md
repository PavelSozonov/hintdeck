# config — настройки, permissions, хуки, терминал

## cfg-notifications — уведомление, когда Claude закончил или ждёт ответа
<!-- n: 92; skip-if: notifications; verified: 2.1.278 -->
Когда Claude завершает задачу или встаёт на запросе разрешения, а тебя нет в терминале, он шлёт уведомление. По умолчанию десктоп-уведомления работают только в Ghostty, Kitty и iTerm2 (в iTerm2 надо включить «Send escape sequence-generated alerts» в профиле). В остальных терминалах поставь `"preferredNotifChannel": "terminal_bell"` в `~/.claude/settings.json`, либо заведи хук `Notification` со своей командой — на macOS подойдёт `osascript -e 'display notification …'`.

**Попробуй:** добавь `preferredNotifChannel` или хук `Notification` и запусти долгую задачу, переключившись в другое окно.

## cfg-keybindings — свои сочетания клавиш в ~/.claude/keybindings.json
<!-- n: 93; skip-if: keybindings; verified: 2.1.278 -->
`/keybindings` создаёт и открывает `~/.claude/keybindings.json`. Формат — массив `bindings` из блоков с `context` (`Chat`, `Global`, `Transcript`, `Confirmation` и др.) и картой «клавиши → действие»: `"ctrl+e": "chat:externalEditor"`. Значение `null` снимает привязку. Изменения применяются без перезапуска. Словесные клавиши редактирования (`Ctrl+W`, `Alt+B`, `Alt+F`, `Alt+D`) переназначить нельзя — действий для них в файле нет.

**Попробуй:** `/keybindings` — и привяжи внешний редактор к удобной тебе клавише.

## cfg-permission-rules — в Bash-правилах ставь * после подкоманды
<!-- n: 94; verified: 2.1.278 -->
Правило разрешений — это `Tool` или `Tool(спецификатор)`; `*` в Bash-правиле совпадает с любым текстом, включая пробелы. Ограничивает правило то, что написано до первой `*`: `Bash(git log *)` разрешает только `git log`, а `Bash(git *)` — любой git, включая push. Учти, что команда, записанная иначе (`git -C . push`), под правило на `git push` не попадёт.

**Попробуй:** открой `/permissions` и проверь, нет ли у тебя слишком широких правил вида `Bash(git *)`.

## cfg-param-rules — deny-правила умеют ловить параметры инструментов
<!-- n: 95; verified: 2.1.278 -->
Deny- и ask-правила могут совпадать по параметру верхнего уровня любого встроенного инструмента: `Agent(model:opus)` — вызовы сабагентов с моделью Opus, `Agent(isolation:worktree)` — сабагенты в worktree, `Bash(run_in_background:true)` — фоновые команды. Значение поддерживает `*`. По основному полю (команда Bash, путь файла) так матчить нельзя — для этого обычный синтаксис.

**Попробуй:** если не хочешь дорогих сабагентов — добавь ask-правило `Agent(model:opus)`.

## cfg-hook-reinject — хук SessionStart с матчером compact возвращает контекст после сжатия
<!-- n: 96; verified: 2.1.278 -->
Сжатие контекста может потерять важные детали. Хук `SessionStart` с `"matcher": "compact"` срабатывает после каждого сжатия, и всё, что его команда напечатает в stdout, попадает в контекст Claude. Вместо `echo` с напоминанием подойдёт любая команда, например `git log --oneline -5`.

**Попробуй:** добавь такой хук с напоминанием о ключевых командах проекта и текущей задаче.

## cfg-stop-hook-gate — хук Stop не даёт закончить, пока проверка не прошла
<!-- n: 97; verified: 2.1.278 -->
Хук `Stop` запускает твой скрипт проверки и блокирует завершение хода, пока скрипт не пройдёт, — это детерминированный гейт, в отличие от просьбы «не забудь прогнать тесты». После 8 блокировок подряд Claude Code всё же завершит ход, чтобы не зациклиться. Более лёгкая альтернатива на одну сессию — `/goal`.

**Попробуй:** если Claude систематически «заканчивает» с красными тестами — заведи Stop-хук с их запуском.

## cfg-settings-precedence — чей settings.json побеждает
<!-- n: 98; verified: 2.1.278 -->
Настройки сливаются из нескольких областей: сначала managed (если есть), затем побеждает более близкая область — local → project → user. Флаги командной строки и переменные окружения — ещё один слой поверх. `/status` показывает, какие источники активны, а `claude doctor` из shell находит битые файлы настроек, не открывая сессию.

**Попробуй:** `/status` — посмотри список активных источников настроек.

## cfg-output-limits — лимит вывода команд, который Claude видит в разговоре, настраивается
<!-- n: 99; verified: 2.1.278 -->
Длинный вывод команды Claude получает не целиком: сверх порога он уходит в файл, а в разговоре остаётся превью. Настройки `bashOutputMaxChars` и `taskOutputMaxChars` поднимают порог для обычных и фоновых команд — до 128K символов (с 2.1.261). Полезно, когда важен весь лог теста, а не его начало.

**Попробуй:** если Claude «не видит» конец длинного вывода — подними `bashOutputMaxChars` в `settings.json`.

## cfg-auto-mode-config — claude auto-mode config показывает действующие правила auto-режима
<!-- n: 100; needs: auto-mode; verified: 2.1.278 -->
`claude auto-mode config` печатает действующую конфигурацию auto-режима с учётом твоих настроек, `claude auto-mode defaults` — встроенные правила классификатора в JSON (`--label <префикс>` — только нужные). `/auto-mode-setup` составляет черновик `autoMode.environment` по проекту и недавним сессиям, а `claude auto-mode reset` убирает секцию `autoMode` из пользовательских настроек.

**Попробуй:** `claude auto-mode config` — сверь, что классификатор знает о твоём окружении.

## cfg-option-as-meta — включи Option as Meta, чтобы заработали Alt-сочетания
<!-- n: 101; needs: macos; verified: 2.1.278 -->
На macOS сочетания с `Alt` (`Alt+B`, `Alt+F`, `Alt+D`, `Alt+Y`, `Alt+P`) требуют, чтобы терминал отдавал Option как Meta; без этого они печатают спецсимволы. Как включить для конкретного терминала — раздел «Enable Option key shortcuts on macOS» в доке terminal-config. После этого заработает и `Option+Enter` для переноса строки.

**Попробуй:** нажми `Alt+B` в строке с текстом: курсор прыгнул на слово назад — всё настроено.

## cfg-cleanup-period — транскрипты и снимки отката живут около 30 дней
<!-- n: 102; verified: 2.1.278 -->
Claude Code удаляет старые транскрипты сессий и файловые снимки чекпойнтов по расписанию — по умолчанию примерно через 30 дней; срок задаёт `cleanupPeriodDays`. После этого `/rewind` к старой точке может ответить «No files were restored». Файлы авто-памяти под чистку не попадают.

**Попробуй:** если возвращаешься к сессиям спустя месяцы — увеличь `cleanupPeriodDays` в настройках.

## cfg-vim-mode — в строке ввода есть vim-режим
<!-- n: 103; verified: 2.1.278 -->
Строка ввода умеет работать в vim-режиме: NORMAL и INSERT, навигация, текстовые объекты, визуальный режим. Включается в `/config` → Editor mode; отдельной команды `/vim` с версии 2.1.92 больше нет.

**Попробуй:** `/config`, найди Editor mode и включи vim на один день.
